### 🎤 30초 요약
통신 과정을 역할별로 나눠서, 문제가 생겼을 때 그 단계만 체크하면 되게 하려고 7계층으로 나눕니다. 순서는 **물리 → 데이터 링크 → 네트워크 → 전송 → 세션 → 표현 → 응용**입니다.

**물리 계층**은 케이블·허브로 데이터를 전기 신호로 바꿔서 주고받는 역할만 하고, **데이터 링크 계층**은 MAC 주소로 프레임을 안전하게 전달합니다(에러검출·재전송·흐름제어). **네트워크 계층**은 라우터와 IP로 목적지까지 가장 빠른 경로를 찾아 패킷을 전달합니다.

**전송 계층**은 TCP·UDP로 포트를 열어서 **엔드투엔드 데이터 전송**을 책임지는 곳입니다. **세션 계층**은 그 전송을 위한 논리적 연결(세션)을 만들고 없애고, **표현 계층**은 인코딩·압축·암호화처럼 데이터 표현을 담당합니다.

마지막 **응용 계층**은 사용자가 실제로 만나는 곳으로, HTTP·FTP 같은 응용 프로토콜을 통해 사용자와의 소통을 담당합니다.


전송 계층이 "엔드투엔드"인 이유는, 네트워크 계층(라우터)이 중간 경유지마다 관여하는 것과 달리 전송 계층은 출발지 포트 ↔ 도착지 포트로 딱 한 번만 관계를 맺기 때문이다. 이게 로드밸런서를 L4/L7로 나누는 배경이 된다 — **L4**는 IP+포트(전송 계층 정보)만 보고 라우팅하고, **L7**은 HTTP 내용(URL, 헤더, 쿠키)까지 보고 라우팅한다. "로드밸런서가 몇 계층에서 동작하나요?"가 OSI 관련 대표 꼬리질문이다.
